현재 화면의 골격을 유지하면서 사용할 색·글자·여백·반경·그림자·모션·문구 규칙을 구체적인 값으로 제안해요. 사용자는 토큰 견본과 대비 수치, 기존 결정의 대체 범위를 보고 단계 3 구현 전에 방향을 선택할 수 있어요(P4·P8·V4·V10·M4).

입력은 [단계 1 감사 보고서](../experiments/style/REPORT.md)와 before PNG 110장이에요. 이번 승인은 **토큰 문서·견본 작성 승인**이며 실제 앱 적용 승인이 아니에요. 작성 결과를 제시한 뒤 **사람 확인 1에서 반드시 멈춰요**.

견본 HTML의 CSS 값은 **제안 문서의 표시용 복제**이고 앱 토큰 정의가 아니에요. 앱의 raw 값·arbitrary 클래스 허용 범위를 넓히지 않아요. foundations의 표와 견본 CSS 값이 같은지 확인해요.

### 설계할 내용

| 영역 | 구체적으로 정할 것 | 근거 |
|---|---|---|
| 색 | 중립 4~5단계, 자체 파랑 강조색 1계열, 작은 빨강·초록·주황 상태 쌍. 기본/호버/선택/포커스·비활성·데이터 역할 구분 | V1·V2·V3·V4·V8·V10 |
| 대비 | 본문·보조·버튼·배지 전경/배경의 실제 사용 쌍, 선택 면 합성값, 포커스·컨트롤 경계 | V10. 비활성 예외를 정상 본문과 구분 |
| 글자 | Pretendard 유지, 표의 업무 밀도를 유지하는 크기·굵기·행간, 제목 위계, tabular-nums | V4·V9 |
| 간격 | 컴포넌트 내부 간격 단계와 적용 역할. 셸 240/56·본문 최대폭 1200·영역 순서는 현행 유지 | P8·V1 |
| 모서리·그림자 | 화면 안 2~3개 반경 단계, 떠 있는 요소에만 그림자 | V5·V6 |
| 모션 | 즉시 피드백·열림/닫힘·로딩의 시간/곡선 이름, 불필요한 진입 삭제, 보통/reduced 대응표 | M1~M6 |
| 문구 | 해요체·능동형·닫기·결과가 보이는 버튼·오류의 이유/해결 안내, 원문 예외 | W1~W12·어드민 예외 |
| 이름 전략 | **기존 CSS 변수·Tailwind 클래스·공개 변형 의미 유지**를 추천. 새 모션 이름만 별도로 제안하고 기존/새 역할 대응표 제공 | P2·P5, 이관 영향 최소화 |
| 의존성 | **새 의존성 0개** 추천. CSS와 기존 tailwindcss-animate로 설계 | P10·M4 |

색상 이외 값의 “대비” 칸은 해당 없음으로 표시하고, 실제 전경/배경 사용 쌍의 대비만 수치로 계산해요. 크기·간격에 의미 없는 대비 수치를 만들지 않아요.
