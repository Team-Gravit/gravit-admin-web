# docs/spec — 명세 인덱스

> 이 폴더는 제품의 **진실의 원천(Source of Truth)** 입니다. 동작·데이터·계약·디자인 사실은 여기서 확인합니다.
> 명세는 **살아 있는 문서**입니다. 기능이 바뀌면 계획서(`docs/plans/PLAN-*.md`)의 "고칠 명세"에 파일과 절을 적고, 구현과 함께 고칩니다.
> 본문 곳곳에서 문서를 **번호 약어**로 인용합니다 — 예: `03 §7`, `04 §11-2`, `01 §6-7`. 아래 표가 그 약어의 매핑입니다.

## 2. 충돌 시 우선순위 (위가 이긴다)
1. **명시적 결정** — `04 §2` 문서 정합성 노트 및 `docs/conventions/decisions.md`(D1~). 같은 주제의 결정이 여러 개면 나중 D 번호가 앞선 것을 대체합니다(예: D11 이 D9 일부를 대체).
   예: 주관식 정답 단일/콤마 = D1 이 DS-02/DS-03 의 "다중 정답 N개" 묘사를 **무시**.
2. **해당 영역의 관할 문서**(위 표).
3. 그 외 문서.
4. **코드 ↔ 명세 충돌** → 명세가 우선. 코드를 명세에 맞추거나, 의도한 변경이면 계획서로 명세를 함께 고칩니다.

## 3. 멈춤 규칙 (추측 금지)
- 명세에 **없거나 서로 모순**이고 위 우선순위로도 해소되지 않으면 → 코드를 쓰지 않고 사용자에게 질문합니다(🙋🏻).
- 명세에 없는 엔드포인트·필드·화면을 추측으로 만들지 않습니다. → `../conventions/antipatterns.md`
- **Figma 는 명세가 아니라 시각(레이아웃·구성) 참조**입니다. 값은 DS-01 토큰을 거치고(raw 값 복사·새 토큰 추가 금지), 동작·데이터·계약에는 권한이 없습니다(01/03/04). 시각 정책·우선순위 = `../conventions/ui-conventions.md`.
- Figma 에 요소가 없는 것은 충돌이 아니라 빈칸입니다 → 명세·DS·토큰으로 시각을 채웁니다(중단·질문 없이). 단 **동작·데이터·계약의 빈칸은 채우지 않고 멈춥니다**(🙋🏻).

## 4. 명세를 고칠 때
- 고치기 전에 계획서 "고칠 명세"에 파일·절·바꿀 내용을 적고 사용자 승인을 받습니다(`write-plan`).
- 명세 간 충돌을 해소하는 결정이면 해당 명세 본문을 고치고, 판단 근거는 `decisions.md` 에 새 D 항목으로 남깁니다.
- `decisions.md` 에만 있는 계약(D7·D8·D9·D11·D12 등)을 `03` 으로 옮길 때는 옮긴 D 항목에 "03 §… 로 반영(날짜)"을 적습니다.
